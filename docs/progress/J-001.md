## What could not be verified

- Native macOS (`darwin-arm64`, `darwin-x64`) and Windows (`win32-x64`, `win32-arm64`) packaging and binary execution (requires macOS and Windows host environments and code signing certificates).
- Full `bun run build` bundle verification under Bun 1.2 due to Bun's incomplete `node:vm` ESM support (requires Bun >= 1.4 or Node execution).

## Known issues

- Bun 1.2.14 in the environment does not provide `bunx` in `PATH` by default (`sudo ln -s /usr/local/bun/bin/bun /usr/local/bin/bunx` was required).
- Linux RPM packaging requires the `rpm` system package (`sudo apt-get install -y --no-install-recommends rpm`).
- In upstream v2.2.5, desktop tests expect `node:sqlite`, which requires a newer Bun runtime (Bun 1.3/1.4).

## Decisions requiring approval

- Ground truth clarification: Upstream v2.2.5 runs `opencode-cli serve --service` as a detached child process daemon rather than running the TypeScript server in-process in Electron's main process. This confirms that Option A in ADR-0001 (Rust desktop shell managing the CLI sidecar) aligns directly with upstream's actual process topology.
